#### 역할

- **요구사항·설계**
  - 현장의 라인 운영 방식을 파악해 요구사항 정의
  - 앞선 레거시 개선 프로젝트의 3계층 구조를 가져와 이 라인에 맞게 재구성
- **Core 개발**
  - MES 서열 수신 TCP 서버 (고정폭 서열 전문 파싱, ACK 응답)
  - PLC 연동 (RS-232 시리얼 주기 폴링, 읽기 전용, 상승엣지 검출)
  - 서열 버퍼 도메인 (중복·말소·되돌리기·재전송 규칙)
  - 커밋 재전송 요청 클라이언트
- **Presentation 개발**
  - 버퍼 목록 ↔ 작업자 화면 전환, 재전송 키패드, 통신 상태 표시
  - 납품 후 작업자 화면 표출 항목 변경 대응
- **테스트·배포**
  - xUnit 테스트 약 60개, 태그 릴리스
  - 현장 시운전

#### 사용 기술

| 구분 | 기술 |
|---|---|
| Language·Framework | C#, .NET 10, WPF |
| Architecture | MVVM (CommunityToolkit.Mvvm), Generic Host DI |
| 통신·설비 | TCP Socket (서버), RS-232 Serial, LS ELECTRIC PLC (Cnet 프로토콜) |
| 테스트 | xUnit |
| CI/CD | GitHub Actions |

#### 주요 기능

- MES 서열 수신·파싱·ACK 응답
- 리미트 스위치 신호마다 선두 서열 한 건 진행
- 연속 중복 서열 무시, 말소 서열 처리
- 완료 서열 히스토리와 되돌리기 (작업자 실수 복구)
- 커밋 재전송 요청 키패드
- 버퍼 목록 ↔ 작업자 화면 전환
- 통신 상태 표시와 일자별·통신·작업 이력 로그
- 재시작 시 히스토리 복원
- 시뮬레이션 모드

<Case no="①" title="라인 운영 방식을 서열 규칙으로 정의">

##### 문제 배경

참조할 레거시가 없어서, 라인과 작업자가 실제로 서열을 어떻게 다루는지부터 시스템 규칙으로 옮겨야 했습니다. 같은 커밋이 연속으로 들어오기도 하고, 이미 받은 서열을 지우는 말소 레코드가 오기도 합니다. 작업자는 실수로 넘긴 서열을 되돌리거나, 특정 커밋부터 MES에 재전송을 요청해야 합니다. 이 경우들을 화면 코드 여러 곳에서 따로 처리하면 버퍼 상태가 어긋날 수 있었습니다.

##### 개선 방법

대기 버퍼와 완료 히스토리를 한 도메인 저장소에 모으고, 외부에는 읽기 전용으로만 노출해 정해진 메서드로만 바뀌게 했습니다.

- 직전과 같은 커밋은 무시합니다.
- 말소 레코드는 버퍼에서 첫 매칭을 지우고, 대상이 없으면 별도 결과로 돌려 로그에 남깁니다.
- 새 서열은 버퍼 끝에 붙이고, 상한에 닿으면 가장 오래된 항목을 지웁니다.
- 넘김은 선두를 히스토리로, 되돌리기는 히스토리의 마지막 항목을 다시 버퍼 선두로 옮깁니다.
- 재전송을 요청할 때는 버퍼를 먼저 비워, 새로 받는 서열과 기존 서열이 섞이지 않게 했습니다.

저장소는 UI 스레드에서만 바뀌도록 상위 계층이 스레드를 넘겨 주고, 재시작 복원 때는 저장 이벤트를 발행하지 않아 불필요한 재저장을 막았습니다. MES에는 파싱에 성공하는 즉시 ACK를 보내므로, 이후 도메인 처리에서 실패하면 반드시 로그를 남겨 조용히 빠지는 서열이 없게 했습니다.

##### 결과

중복·말소·되돌리기·재전송 규칙을 단위 테스트 11개로 고정했습니다.

</Case>

<Case no="②" title="리미트 스위치 신호마다 정확히 한 건씩 진행">

##### 문제 배경

PLC 상태 워드를 주기적으로 읽어 리미트 스위치가 켜졌는지 판단합니다. 켜져 있는 동안 폴링할 때마다 서열을 넘기면, 차 한 대가 지나갈 때 서열이 여러 건 넘어갑니다. 또 프로그램 시작 직후나 통신이 끊겼다 복구된 직후에 접점이 이미 켜져 있으면, 차가 지나가지 않았는데도 서열이 넘어갈 수 있었습니다. 앞선 연료탱크 이식본은 재시작 때 접점이 이미 켜져 있으면 첫 폴링을 엣지로 볼 수 있는 구조였는데, 신규 구축인 이 시스템에서는 처음부터 막기로 했습니다.

##### 개선 방법

- 꺼짐에서 켜짐으로 바뀌는 상승엣지에서만 한 건을 진행합니다.
- 첫 표본은 기준값으로만 저장하고 엣지로 보지 않아, 시작 직후의 오진행을 막았습니다.
- 통신 오류가 나면 채널을 닫고 다음 요청에서 자동으로 다시 연결하며, 이때 엣지 검출기를 초기화해 복구 직후 이미 켜진 접점으로 서열이 넘어가지 않게 했습니다.
- 상태 비트 해석과 엣지 검출은 통신과 분리된 순수 로직으로 두어 단위 테스트로 검증했습니다.
- PLC에는 값을 쓰지 않고 읽기만 해, 설비 동작에 영향을 주지 않게 했습니다.

##### 결과

시작·복구 직후 오진행을 막는 규칙을 테스트로 고정했고, 통신이 끊겨도 사람 손 없이 다시 붙습니다.

</Case>

#### 납품 후 변경 요청 대응

고객사 요청으로 작업자 화면의 표출 항목을 현장에 필요한 항목으로 바꾸고, 후속 서열을 더 볼 수 있게 표시 행 수를 늘렸습니다. 파서가 전문의 사양 필드를 모두 읽어 두고, 화면에 무엇을 어떻게 보일지는 표시용 모델과 화면이 정하는 구조라 통신·파싱 코드를 건드리지 않고 반영했습니다.
