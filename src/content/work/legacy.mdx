#### 역할

- **레거시 분석·설계**
  - 원본 동작을 분석해 보존할 동작과 고칠 결함을 구분하고, 판단 근거를 문서로 남김
  - 보존한 비직관적 동작을 대응 테스트로 고정 (바꾸면 테스트가 깨지도록)
  - Core / Presentation / Tests 3계층 구조 설계
- **통신 구현 (외부 통신 라이브러리 없이)**
  - MES 서열 수신 TCP 서버, 자동 재연결 TCP 클라이언트
  - Siemens PLC Fetch/Write 통신 코덱
  - 2D 바코드 스캐너 시리얼 통신
- **도메인·화면 개발**
  - 서열 버퍼와 서열 동기화, 이종 판정 흐름
  - 풀스크린 현황판 2대, 진단 도구 (PLC 메모리 실시간 보기, 통신 상태 표시)
  - 기존 INI 설정 자동 이관
- **테스트·배포**
  - xUnit 테스트 약 225개 (두 시스템 합계, TCP 루프백 통합 테스트 포함)
  - 태그 릴리스, 현장 시운전

#### 사용 기술

| 구분 | 기술 |
|---|---|
| Language·Framework | C#, .NET 10, WPF |
| Architecture | MVVM (CommunityToolkit.Mvvm), Generic Host DI |
| 통신·설비 | TCP Socket (서버·클라이언트), Siemens PLC (Fetch/Write), RS-232 Serial (2D 바코드 스캐너) |
| 테스트 | xUnit, TimeProvider |
| CI/CD | GitHub Actions |

#### 주요 기능

- **일반현황판**
  - MES 서열 수신·파싱·ACK 응답, 모델 코드로 차종 분류
  - PLC 주기 폴링으로 공정별 작업 상태를 현황판 색상으로 표시, PLC에 생존 신호 송신
  - 기준 호스트와 서열 동기화, 버퍼에 없는 서열은 MES에 자동 재요청
  - 풀스크린 현황판 2대, 모니터 할당 변경
- **연료탱크 이종 방지**
  - 여러 조각으로 나뉘어 오는 서열 전문 재조립·파싱
  - PLC 신호에 맞춰 스캐너 트리거, 스캔한 서열코드와 버퍼 선두의 연료탱크 사양 대조
  - 판정 결과(대기·OK·NG·오류)를 PLC로 반영
- **공통**
  - 재전송 키패드, PLC 메모리 실시간 보기, 통신 상태 표시, 로그, 상태 복원, 시뮬레이션 모드

#### 시스템 구조

- 통신·프로토콜·도메인은 WPF와 무관한 Core에 두고, 의존 방향을 Presentation → Core 한쪽으로 고정했습니다. 테스트는 Core만 참조합니다.
- 백그라운드 통신 이벤트는 UI 스레드로 넘긴 뒤에만 도메인 상태를 바꾸게 해, 도메인 저장소를 잠금 없이 한 스레드에서 다룹니다.
- 이벤트 구독자의 예외는 통신 루프로 번지지 않게 격리했습니다.
- 설정·상태 파일이 깨지면 백업한 뒤 기본값으로 시작하고, 저장은 임시 파일에 쓴 뒤 원자적으로 교체합니다. 로깅이나 저장이 실패해도 라인 동작은 막지 않습니다.
- 이 구조를 이후 언더바디와 HEV 현황판에서도 가져와 썼습니다.

<Case no="①" title="원본 동작은 보존하고 결함만 고친 서열 동기화 (일반현황판)">

##### 문제 배경

일반현황판은 같은 라인의 기준 호스트에서 현재 커밋 번호를 받아 버퍼 서열을 맞춥니다. 원본은 받은 값을 숫자로 바꿀 때 검증하지 않아서, 숫자가 아닌 값이 오면 0으로 바뀌고 오프셋 보정을 거쳐 존재하지 않는 커밋 번호가 되었습니다. 그러면 "버퍼에 없는 서열"로 판정되어 버퍼 전체를 지우고 재요청하는 경로를 탈 수 있었습니다.

한편 원본 동기화에는 비직관적이지만 현장이 오래 검증한 규칙도 있었습니다. 같은 커밋이 여러 개면 마지막 위치를 기준으로 맞추고, 받은 번호에 고정 오프셋을 보정하는 식입니다. 결함과 함께 이런 규칙까지 "정리"하면 라인 동작이 바뀔 수 있었습니다.

##### 개선 방법

- **보존:** 마지막 위치 기준 정렬, 오프셋 보정, 말소 시 첫 매칭 제거 같은 원본 동작은 그대로 옮기고, 대응 테스트와 코드 주석으로 고정했습니다. 나중에 누가 바꾸려 하면 테스트가 먼저 깨집니다.
- **수정:** 받은 값을 정규화하는 단계에서 숫자 여부와 범위를 검증하고, 무효한 값은 무시하도록 했습니다. 버퍼를 비우는 것처럼 되돌릴 수 없는 동작 앞에서는 입력을 먼저 검증합니다.
- **분리:** 동기화 판정은 유지·N칸 이동·재요청 중 하나를 결과로 돌려주고, 재요청 송신은 호출하는 쪽이 하도록 나눠 판정 로직만 단위 테스트할 수 있게 했습니다.
- 고친 항목마다 판단 근거를 문서로 남겨, 다음 담당자가 왜 그렇게 했는지 알 수 있게 했습니다.

##### 결과

잘못된 동기화 값 하나로 버퍼 전체가 지워지는 경로를 막으면서도, 현장이 익숙한 동기화 동작은 그대로 유지했습니다.

<Case no="②" title="여러 스레드에서 오는 신호를 한 판정 흐름으로 (연료탱크 이종 방지)">

##### 문제 배경

판정 한 번에 세 가지 입력이 엮입니다. PLC 폴링에서 오는 서열 이동·스캔 시작 신호, 시리얼로 오는 스캐너 응답, 그리고 TCP로 받아 쌓은 버퍼 선두의 연료탱크 사양입니다. 이 입력들은 서로 다른 스레드에서 들어오기 때문에, 각자 다른 곳에서 처리하면 판정이 왜 그렇게 났는지 따라가기 어렵고 장치 없이는 검증할 수도 없었습니다. 또 서열 전문은 크기가 커서 TCP 세그먼트 여러 개로 나뉘어 도착했습니다.

##### 개선 방법

스캔·PLC·버퍼를 잇는 흐름을 조정자 클래스 하나에 모으고, 모든 처리를 UI 스레드에서만 실행하게 했습니다.

- **서열 이동 신호:** 대상 차종이 선두에 올 때까지 서열을 넘기고, 넘길 때마다 PLC의 판정 결과를 대기로 되돌립니다.
- **스캔 시작 신호:** 스캐너를 켜고 무응답 타임아웃을 겁니다.
- **스캐너 응답:** 읽은 서열코드를 선두의 사양과 완전 일치로 비교해 OK/NG를 PLC에 씁니다. 스캐너가 명시적으로 오류를 돌려주면 오류로 씁니다.
- **스캐너 무응답:** 원본처럼 대기로 남겼습니다. 현장·설비 담당과 합의 없이 바꾸지 않을 동작이라 테스트로 고정했습니다.

PLC 쓰기, 스캐너 명령, 시간, 스레드 전환을 모두 주입받게 해, 소켓과 장치 없이도 타임아웃까지 결정적으로 테스트할 수 있게 했습니다.

나뉘어 오는 전문은 STX부터 ETX까지 누적해 다시 조립했습니다. 조립은 동기 루프에서 끝내고 완성된 프레임만 비동기로 처리해, 처리 도중 다음 조각이 조립 버퍼를 오염시키지 않게 했습니다. 버퍼가 상한을 넘으면 비우고 다음 시작 문자부터 다시 받습니다.

##### 결과

판정 경로가 한 곳에 모여 로그와 테스트로 추적할 수 있게 되었습니다. 판정 흐름은 조정자 테스트 9개와 비교 규칙 테스트 5개로 고정했습니다.

</Case>
